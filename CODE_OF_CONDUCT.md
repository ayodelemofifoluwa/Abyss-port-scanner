# Code of Conduct

## Our standard

Be respectful. Assume good faith. Disagree about code without making it personal.

This project deals with security tooling, which attracts a wide range of
intentions. Contributions and discussion should stay focused on legitimate,
authorized security testing and education. Requests to add features whose
primary purpose is unauthorized access (credential brute-forcing, exploit
automation, etc.) will be declined regardless of how they're framed — see
CONTRIBUTING.md's scope guardrails.

## Reporting issues

If someone's conduct in issues, PRs, or discussions isn't in the spirit of
the above, open an issue tagged `conduct` or contact the maintainers directly.

## Scope

This applies to all project spaces: the GitHub repo, issues, pull requests,
and any associated discussion channels.
